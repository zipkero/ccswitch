# profile-store

## 1. 범위

ccswitch의 프로필 저장소와 그 위에 놓이는 `add`, `list`, `rm` 세 명령을 다룬다.

다루는 영역은 다음과 같다.

- 프로필 이름 규칙과 예약 이름
- 프로필 디렉토리의 위치 산출
- 프로필 메타데이터의 저장 위치와 등록·조회·삭제
- 위 세 명령의 성공·실패 출력과 종료 코드

프로필의 존재 여부·위치·이름에 대한 단일 기준을 이 feature가 소유한다. 이후
profile-launcher가 이 저장소를 읽어 실행 대상을 정한다.

### 입력 맥락

- 현재 저장소에는 코드가 없다. 신규 Go 프로젝트의 첫 feature다.
- 참고 구현으로 `binoyPeries/ccswitch`(Go, cobra)를 읽었다. 메타데이터를 `profiles.json`에
  두고 프로필 디렉토리를 홈 아래 `.claude-<name>`에 두는 구조다. 설계를 참고하되 코드를
  가져오지 않고 직접 구현하기로 정했다.
- 확인한 동작(Claude Code 2.1.220, Windows): `CLAUDE_CONFIG_DIR`을 빈 디렉토리로 지정하고
  `claude`를 실행하면 그 디렉토리에 새 `.claude.json`이 생기고 홈 루트의 `~/.claude.json`은
  참조하지 않는다. 자격증명은 설정 디렉토리 안의 `.credentials.json` 평문 파일이다.
- 검토했으나 접은 접근:
  - 자격증명 파일이나 Keychain 항목을 직접 교체하는 방식. Claude Code가 실행 중에 계속 쓰는
    파일을 밖에서 덮어쓰게 되어 토큰 갱신과 경합하면 로그인 상태가 깨진다.
  - 레지스트리에 설정 디렉토리를 영구 기록해 기본 계정을 바꾸는 방식. 사용자가 셸 프로필에
    한 줄을 추가하면 같은 결과를 얻을 수 있고, 도구가 쓰면 눈에 보이지 않는 전역 상태가 남는다.

## 2. 목표

계정별 작업 공간을 이름으로 만들고, 무엇이 있는지 확인하고, 지울 수 있게 한다.

사용자가 얻는 결과는 "업무 계정용 자리를 하나 만들어 두었고 그 자리가 어디인지 안다"는 것이다.
이 자리가 있어야 로그인과 실행을 그 안에서 할 수 있다. 이 feature 하나만으로는 계정 전환이
완성되지 않지만, 전환의 대상이 되는 단위가 여기서 정의된다.

## 3. 제약

- Windows에서 동작해야 한다. macOS는 이후 마일스톤이지만, 프로필 디렉토리와 메타데이터의
  위치가 플랫폼마다 다르다는 점은 이번 범위에서 반영한다.
- Go로 구현한다.
- 관리자 권한을 요구하지 않는다.
- Claude Code의 자격증명과 설정 파일 내용을 읽거나 쓰지 않는다. 프로필 디렉토리는 만들되 그
  안을 채우지 않으며, 안에 무엇이 들어갈지는 Claude Code가 정한다.
- 프로필 디렉토리는 사용자 홈 아래에 프로필 이름으로 구분되는 경로를 쓴다. 메타데이터는
  플랫폼의 표준 사용자 설정 위치에 둔다.
- `default`는 예약 이름이다. 사용자 프로필로 만들 수 없으며, Claude Code의 기본 설정
  디렉토리를 가리키는 항목으로 취급한다.
- 삭제는 되돌릴 수 없다. 프로필 디렉토리에는 자격증명과 세션 기록이 들어 있으므로, 사용자가
  의도를 확인하지 않은 상태에서 지우지 않는다.
- 인자 해석은 POSIX 관례를 따른다. `-`로 시작하는 값은 옵션으로 먼저 해석되므로, 그런 값을
  프로필 이름으로 넘기려면 `--` 뒤에 두어야 한다. 이 구간은 인자 파서가 담당하며 이름 규칙
  검증보다 앞선다.

## 4. 제외 범위

- 프로필을 지정해 Claude Code를 실행하는 것 (profile-launcher)
- 프로필 단위 로그인·로그아웃, 삭제 시 자격증명 정리 (profile-auth)
- `list`에 계정 이메일·플랜 등 계정 정보를 표시하는 것. 계정 정보를 읽으려면 Claude Code의
  비공식 내부 파일 포맷에 의존해야 하므로 이번 범위에서 뺀다 (profile-auth)
- 설정 자산 공유와 링크 구성. 이번 `add`는 빈 디렉토리만 만든다 (shared-assets)
- 기존 기본 설정 디렉토리를 이름 있는 프로필로 승격하는 것 (profile-import)
- 기계 판독용 출력 형식(JSON 등). 이번 `list`는 사람이 읽는 출력만 낸다
- macOS·Linux에서의 동작 검증 (macos-support)

## 5. 완료 조건

1. `ccswitch add <name>`이 성공하면 해당 프로필의 디렉토리가 만들어지고, 이어서 실행한
   `ccswitch list` 출력에 그 이름과 디렉토리 경로가 나타난다.
2. 이름 규칙에 맞지 않는 이름으로 `add`를 실행하면 프로필이 만들어지지 않고, stderr에
   무엇이 잘못되었는지와 허용되는 이름 형식이 표시되며 종료 코드가 0이 아니다.
3. 예약 이름 `default`로 `add`를 실행하면 프로필이 만들어지지 않고, stderr에 예약된 이름임이
   표시되며 종료 코드가 0이 아니다.
4. 이미 등록된 이름으로 `add`를 실행하면 기존 프로필의 디렉토리와 등록 내용이 바뀌지 않고,
   stderr에 이미 존재한다는 내용이 표시되며 종료 코드가 0이 아니다.
5. 프로필 디렉토리가 놓일 자리에 비어 있지 않은 디렉토리가 이미 있으면 `add`가 그 내용을
   건드리지 않고 실패하며, stderr에 해당 경로와 사용자가 취할 수 있는 조치가 표시된다.
6. 등록된 프로필이 하나도 없어도 `ccswitch list`는 실패하지 않고, `default` 항목을 포함한
   출력을 내며 종료 코드가 0이다.
7. `ccswitch rm <name>`은 사용자가 삭제 의도를 확인하기 전에는 디렉토리와 등록 항목 어느
   쪽도 지우지 않는다. 확인을 건너뛰는 명시적 방법이 있으며, 그 경우 프롬프트 없이 삭제된다.
8. `rm`이 성공하면 프로필 디렉토리와 등록 항목이 함께 사라지고, 이어서 실행한 `list` 출력에
   그 이름이 나타나지 않는다.
9. 등록되지 않은 이름으로 `rm`을 실행하면 stderr에 그 이름을 찾을 수 없다는 내용이 표시되고
   종료 코드가 0이 아니다.
10. `rm default`는 거부되고 Claude Code의 기본 설정 디렉토리가 그대로 남는다.
11. 메타데이터 파일이 아직 없거나 읽을 수 없는 상태에서 명령을 실행해도 프로세스가 비정상
    종료하지 않고, 사용자가 상황을 알 수 있는 메시지가 표시된다.
12. 등록된 프로필의 디렉토리가 밖에서 지워진 상태여도 `list`가 실패하지 않고, 그 프로필이
    정상이 아님을 사용자가 구별할 수 있다.
