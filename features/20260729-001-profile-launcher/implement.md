  - 검증 조건:
    - 결과: 등록된 이름으로 실행하면 조회로 확정된 실행 파일 경로에 `--` 뒤 값이 순서와 개수

      디렉토리가 여전히 없음을 확인하는 케이스를 포함한다. `default`가 `add`·`rm`에서는 계속
      예약 이름으로 거부되는 것을 기존 테스트로 함께 확인한다.

  - 목적: 자식이 0이 아닌 코드로 끝나면 ccswitch가 같은 코드로 끝나면서 stderr에 아무 메시지도

  - 접근: 0이 아닌 자식 종료 코드만 나르는 error 타입을 두고, 종료 코드 매핑이 sentinel 표보다
    먼저 그것을 본다. `use`는 프레임워크의 기본 오류 출력을 끄고 자기 실패 메시지를 직접 내며,
    나머지 커맨드의 출력 경로는 건드리지 않는다.
  - 검증 조건:
    - 결과: 자식 종료 코드 0·1·2·130에 대해 ccswitch 종료 코드가 각각 같은 값이고, 0이 아닌
      경우에도 stdout·stderr가 모두 비어 있다. 실행을 거부한 경우에만 stderr에 접두사가 붙은
      한 줄이 나오고 사용법 전문은 나오지 않는다.
    - 확인: 대역이 정해진 코드를 돌려주는 table-driven 테스트로 코드 중계를 덮고, 더해서 실제
      프로세스 왕복을 한 번 검증한다 — 테스트 바이너리 자신을 조회 결과 실행 파일로 지정해
      자식 모드로 띄우고, 자식이 받은 환경과 인자를 파일에 적고 정해진 코드로 끝나게 해서,
      주입된 `CLAUDE_CONFIG_DIR`과 `--` 뒤 인자가 실제로 자식 프로세스에 도달하는지와 그
      종료 코드가 ccswitch의 종료 코드로 나오는지를 함께 확인한다. 종료 코드 매핑에 분기를
      더한 뒤에도 기존 0~5 매핑 테스트와 `add`·`list`·`rm` 테스트가 수정 없이 통과한다.
  - 참조: SPEC §5.4, §5.5 / ANALYSIS §2, §3, §5 D7, D16

      경로에 같은 이름의 파일을 놓고 `use` → 코드 6이고 그 파일이 그대로 남음. (4) 형식 위반
      이름 → 코드 2, 대역 기록 없음. (5) 손상된 등록 파일 → 코드 1이고 그 파일이 덮어써지지
