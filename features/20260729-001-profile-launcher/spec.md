# profile-launcher

## 1. 범위

프로필을 지정해 Claude Code를 실행하는 `use` 명령과 그 실행 경계를 다룬다.

다루는 영역은 다음과 같다.

- 프로필 이름으로 실행 대상 설정 디렉토리를 정하는 것 (프로필의 존재·위치 판정 자체는
  profile-store가 소유하고 여기서는 읽는다)
- Claude Code 프로세스에 넘기는 환경 — 주입할 환경변수와 제거할 환경변수
- 사용자가 준 인자를 Claude Code에 전달하는 것
- 자식 프로세스의 입출력, 종료 코드, 인터럽트 처리
- 실행하지 못하는 상황의 출력과 종료 코드
- README의 상태 문구와 사용 절차를 실제 동작과 일치시키는 것

### 입력 맥락

- profile-store가 완료되어 `add`·`list`·`rm`이 동작한다. 프로필 이름·경로·등록 상태의 단일
  기준은 그쪽에 있다.
- 확인한 동작 (Claude Code 2.1.220):
  - Windows에서 `CLAUDE_CONFIG_DIR`을 빈 디렉토리로 지정해 실행하면 그 디렉토리에 새
    `.claude.json`이 생기고 홈 루트의 `~/.claude.json`은 참조하지 않는다. 자격증명은 그
    디렉토리 안 `.credentials.json`이다.
  - macOS에서는 `CLAUDE_CONFIG_DIR`이 설정되면 Keychain 서비스 이름에 그 경로 문자열의
    `sha256[:8]`이 붙어 프로필마다 항목이 갈린다. 경로를 정규화하지 않으므로 뒤 슬래시
    하나만 달라도 다른 항목이 된다.
  - 로컬 Windows 환경의 설치 형태는 네이티브 실행 파일(`~/.local/bin/claude.exe`)이다.
- `/spec-init` 전 논의에서 정한 방향:
  - Windows에는 exec 치환이 없다. 따라서 부모가 사라지며 자기 자리를 넘기는 방식은 쓸 수 없고,
    자식 프로세스로 띄운 뒤 부모가 남아 종료 코드를 중계한다.
  - Go의 `CreateProcess` 호출에 `CREATE_NEW_CONSOLE`이 들어가지 않으므로 자식은 부모 콘솔을
    공유한다. 새 창은 뜨지 않는다.
  - 부모의 stdin·stdout·stderr 핸들을 그대로 물려준다. 파이프로 감싸면 Claude Code의 TUI
    판정이 비대화형으로 떨어져 화면이 깨진다.
  - 같은 콘솔에 붙은 프로세스는 Ctrl+C를 함께 받는다. 부모는 인터럽트에 먼저 끝나지 않고
    자식이 정리하고 나가기를 기다린다.
  - default 프로필은 변수를 주입하는 대신 환경에서 제거한다. 기본 경로를 값으로 넣으면
    Claude Code가 평소와 다른 자격증명 항목과 다른 설정 파일 위치를 보게 된다.

## 2. 목표

로그아웃과 재로그인 없이 명령 하나로 계정을 바꿔 Claude Code를 실행할 수 있게 한다.

profile-store가 계정별 자리를 정의했지만 그 자리를 쓰는 경로가 없어, 지금은 프로필을 만들어도
계정 전환에 쓸 수 없다. 이 feature가 그 마지막 조각이며, 여기까지 오면 사용자가 얻는 결과는
"업무 계정으로 일하려면 `ccswitch use work`를 치면 된다"는 것이다.

## 3. 제약

- Windows에서 동작해야 한다. macOS 실기 검증은 이후 마일스톤이지만, 플랫폼마다 갈리는
  지점(주입하는 경로 문자열, 프로세스 실행 방식)은 이번 범위에서 반영한다.
- Go로 구현한다.
- 관리자 권한을 요구하지 않는다.
- Claude Code의 자격증명과 설정 파일 내용을 읽거나 쓰지 않는다. 로그인은 실행된 Claude Code
  세션 안에서 사용자가 직접 한다.
- 같은 프로필에 대해 주입하는 경로는 항상 같은 문자열이어야 한다. macOS에서 Keychain 항목이
  경로 문자열의 해시로 갈리므로, 문자열이 흔들리면 같은 프로필이 다른 자격증명을 보게 된다.
- `default` 프로필은 환경변수를 주입하지 않고 환경에서 제거한다.
- 호출 환경에 남아 있는 인증 관련 환경변수(`CLAUDE_SECURESTORAGE_CONFIG_DIR` 포함)를 제거해,
  ccswitch를 부른 셸의 설정이 프로필 격리를 깨지 않게 한다.
- 자식 프로세스로 실행한다는 사실이 사용자 눈에 새 창이나 깨진 화면으로 나타나지 않아야 한다.
- 인자 해석은 POSIX 관례를 따른다. `--` 뒤의 값은 해석하지 않고 그대로 Claude Code에 넘기며,
  `--` 없이 주어진 알 수 없는 옵션은 ccswitch가 거부한다.
- 실행 대상 프로필의 존재 여부·경로 판정은 profile-store의 기준을 그대로 쓰고 이 feature에서
  다시 정의하지 않는다.
- `use`는 프로필 상태를 고치지 않는다. 등록되어 있지만 디렉토리가 없는 프로필은 디렉토리를
  만들어 진행하지 않고 거부한다.

## 4. 제외 범위

- 프로필 단위 로그인·로그아웃 (profile-auth)
- 목록에 계정 이메일·플랜 등 계정 정보를 표시하는 것 (profile-auth)
- 설정 자산 공유와 링크 구성 (shared-assets)
- 기존 기본 설정 디렉토리를 이름 있는 프로필로 승격하는 것 (profile-import)
- 기본 프로필을 레지스트리나 셸 설정에 영구 기록하는 것 (ROADMAP 보류 범위)
- 자격증명 파일이나 Keychain 항목을 직접 조작하는 것 (ROADMAP 보류 범위)
- Claude Code 실행 파일의 위치를 사용자가 따로 지정하는 수단. PATH 조회 결과를 쓴다
- Claude 데스크톱 앱과 IDE 확장 (ROADMAP 제외 범위)
- macOS·Linux에서의 실기 검증 (macos-support)

## 5. 완료 조건

1. `ccswitch use <name>`이 등록된 프로필로 Claude Code를 실행하고, 그 세션이 해당 프로필
   디렉토리를 설정 디렉토리로 쓴다 — 세션을 쓴 뒤 그 디렉토리에 기록이 쌓이는 것으로 관찰된다.
2. 이름을 생략한 `ccswitch use`는 default로 실행되며, 그 세션은 Claude Code의 기본 설정
   디렉토리를 쓰고 세션 환경에 `CLAUDE_CONFIG_DIR`이 남지 않는다.
3. `--` 뒤에 준 인자가 Claude Code에 그대로 전달된다 — `ccswitch use work -- --model opus`가
   모델 지정으로 반영된다.
4. Claude Code가 끝났을 때의 종료 코드가 `ccswitch`의 종료 코드로 그대로 나온다.
5. 실행 중 새 콘솔 창이 뜨지 않고, 같은 창에서 TUI가 정상 동작한다 — 화면 갱신, 키 입력,
   창 크기 변경이 프로필을 거치지 않고 `claude`를 직접 실행한 것과 구별되지 않는다.
6. 실행 중 Ctrl+C를 눌렀을 때 ccswitch가 자식보다 먼저 끝나 자식 프로세스를 남기지 않는다.
7. 등록되지 않은 이름으로 `use`를 실행하면 Claude Code가 실행되지 않고, stderr에 그 이름을
   찾을 수 없다는 내용이 표시되며 종료 코드가 0이 아니다.
8. 등록되어 있지만 디렉토리가 없는 프로필로 `use`를 실행하면 디렉토리를 만들지 않고 Claude
   Code도 실행하지 않으며, stderr에 해당 경로와 사용자가 취할 수 있는 조치가 표시되고 종료
   코드가 0이 아니다.
9. PATH에서 Claude Code 실행 파일을 찾을 수 없으면 stderr에 무엇을 찾지 못했는지가 표시되고
   종료 코드가 0이 아니다.
10. 호출한 셸에 `CLAUDE_CONFIG_DIR`이나 `CLAUDE_SECURESTORAGE_CONFIG_DIR`이 이미 설정되어
    있어도 그 값이 실행된 세션에 영향을 주지 않는다.
11. 서로 다른 두 계정으로 각각 로그인한 프로필을 번갈아 실행하면, 각 세션의
    `claude auth status`가 서로 다른 계정을 보고하고 한쪽 세션 기록이 다른 쪽에 나타나지
    않는다. 두 계정 로그인이 필요하므로 사용자 실기 확인으로 관찰한다.
12. README의 상태 문구와 사용 절차가 실제 동작과 일치한다 — `use`로 계정을 바꿔 실행할 수
    있다는 것과 그 사용법이 적혀 있고, 아직 없는 명령을 쓸 수 있는 것처럼 적지 않는다.
