# shared-assets

## 1. 범위

설정 자산을 프로필 사이에 공유한다 — 새 프로필이 default 설정 디렉토리의 스킬·커맨드·에이전트·
규칙·메모리·설정을 물려받고, 물려받은 것을 원본과 다시 맞추는 것.

다루는 영역은 다음과 같다.

- 프로필을 만들 때 공유 자산을 구성하는 것 (디렉토리 링크, `CLAUDE.md` 참조, 루트 파일 복사)
- 루트 파일 복사 목록 — ccswitch 기본 목록과 사용자 등록 목록
- 이미 있는 프로필의 공유 자산을 원본과 다시 맞추는 것 (`sync`)
- 공유 자산이 있는 프로필을 지울 때 원본을 보존하는 것
- 위 동작들의 성공·실패 출력과 종료 코드

### 입력 맥락

- profile-store·profile-launcher·profile-auth가 완료되어 `add`·`list`·`use`·`rm`·`login`·
  `logout`이 동작한다. 이 feature는 `add`가 만드는 빈 디렉토리를 채우고 `rm`의 삭제 경로를
  공유 자산에 안전하게 만든다.
- 공유 원본은 default 설정 디렉토리(`~/.claude`)다. 원본 쪽은 이 feature가 고쳐 쓰지 않는다.
- 확인한 동작 (CI, 2026-10-23, Go 1.24.13 / 1.27.3, `experiment/junction-removeall` 브랜치):
  - Windows junction은 `os.Lstat`에서 `ModeIrregular`이고 `ModeSymlink`도 `ModeDir`도 아니다.
    `os.Stat`은 대상을 따라가 디렉토리로 보고한다.
  - junction이나 symlink를 담은 프로필 디렉토리를 `os.RemoveAll`로 지워도 링크 대상은 남는다.
    링크 자체에 `os.Remove`·`os.RemoveAll`을 걸어도 링크만 지워진다. 대상이 사라진 깨진 링크가
    있어도 삭제가 실패하지 않는다.
- 사용자와 정한 방향 (2026-10-23, ROADMAP에 반영):
  - 루트 파일은 복사 목록에 든 것만 복사한다. 목록은 ccswitch 기본 목록(`settings.json`,
    `keybindings.json`)에 사용자 등록 파일을 더한 것이다. 패턴·블랙리스트 같은 자동 판정은 쓰지
    않는다 — 계정에 딸린 파일이 다른 프로필로 새는 사고와 맞바꿀 이득이 없다.
  - 복사하지 않은 루트 파일을 알리는 출력은 두지 않는다.
  - 기존 `~/.claude`를 이름 있는 프로필로 승격하는 것(`import`)은 하지 않는다. ROADMAP 보류
    범위로 옮겼다.

### 선행 확인 — SPEC 확정 전에 실기로 관찰해야 하는 것

아래 셋은 Claude Code 이슈 트래커에 반대되는 보고가 있어, 결과에 따라 공유 수단이 바뀐다.
코드가 아니라 사용자가 쓰는 Claude Code 버전에서 직접 관찰한다.

1. `CLAUDE_CONFIG_DIR`을 준 세션이 `~/.claude/CLAUDE.md`도 읽는가. 읽는다는 보고가 여럿 있다
   (anthropics/claude-code #30230, #59701, #47056). 읽는다면 `CLAUDE.md`는 이미 공유되는 셈이고,
   프로필 쪽에 참조를 두면 같은 지침이 두 번 들어간다 — 참조를 두지 않는 쪽으로 바뀐다.
2. 프로필의 `skills/`(그리고 `commands/`·`agents/`·`rules/`) 디렉토리 자체가 링크일 때 Claude
   Code가 그 안을 읽는가. 디렉토리 전체가 symlink면 사용자 스킬이 로드되지 않는다는 회귀 보고가
   있다 (#38051, v2.1.69 이후). Windows의 Node는 junction을 symlink로 보므로 junction에도 같은
   문제가 걸릴 수 있다. 읽지 않는다면 디렉토리는 실제 디렉토리로 두고 그 안의 항목을 하나씩
   링크하는 방식으로 바뀌며, 원본에 새 항목이 생기면 `sync`가 있어야 따라온다.
3. 2에서 항목 단위 링크를 쓸 때, 링크된 스킬 폴더가 로드되는가 (#14836은 `/skills` 목록에만
   안 보이고 모델은 쓸 수 있다고 보고한다).

## 2. 목표

새 프로필이 빈 상태가 아니라 default의 작업 환경을 가진 상태로 시작한다.

지금은 `add`로 만든 프로필에 스킬·커맨드·에이전트·메모리·설정이 하나도 없어, 계정을 바꾸면
작업 환경도 함께 초기화된다. 이 feature 뒤에는 계정만 갈리고, 원본에서 고친 스킬·커맨드·
에이전트·규칙·메모리는 모든 프로필에 반영되며, 설정은 프로필마다 고쳐 쓰다가 원할 때 원본에
다시 맞출 수 있다.

## 3. 제약

- Windows에서 동작해야 한다. macOS 실기 검증은 이후 마일스톤이다.
- Go로 구현한다.
- 관리자 권한이나 Windows 개발자 모드를 요구하지 않는다 — Windows 디렉토리 링크는 junction을
  쓴다. 파일에는 junction을 쓸 수 없으므로 파일은 복사하거나 참조한다.
- 공유 원본(`~/.claude` 쪽 실체)을 만들거나 고치거나 지우지 않는다.
- 삭제 계열 동작은 링크를 따라 들어가 공유 원본을 지우지 않는다. 이것이 테스트로 확인된다.
  Windows에서 링크 판정은 `ModeSymlink`만으로 하지 않는다 — junction은 `ModeIrregular`로 온다.
- 계정에 딸린 파일(자격증명, `.claude.json`, 세션 기록, 프로젝트 상태)은 어떤 경로로도 다른
  프로필로 옮기지 않는다.
- 복사한 파일은 프로필이 소유한다. `sync`를 부를 때만 원본 기준으로 덮어쓴다.
- 기존 명령의 출력과 종료 코드 계약을 깨지 않는다. 새 실패 원인은 새 종료 코드로 구분한다.
- 등록 정보 파일 스키마를 바꾼다면 버전을 올리고, 이전 버전 파일을 읽을 수 있어야 한다.

## 4. 제외 범위

- 기존 기본 설정 디렉토리를 이름 있는 프로필로 승격하는 것 (ROADMAP 보류)
- 계정에 딸린 데이터(세션 기록, 프로젝트 상태, MCP 서버 설정이 든 `.claude.json`)의 공유
- 원본에서 지운 자산을 프로필 쪽에서 자동으로 지우는 동기화. `sync`는 원본을 기준으로 맞추는
  명시적 동작이며 백그라운드 감시를 하지 않는다
- 프로필마다 공유 대상을 다르게 고르는 것. 공유 대상 디렉토리와 복사 목록은 모든 프로필에 같다
- `plugins/`·`hooks/`·`output-styles/` 등 위 목록에 없는 디렉토리의 공유
- 복사하지 않은 루트 파일을 알리는 출력
- macOS·Linux에서의 실기 검증 (macos-support)

## 5. 완료 조건

1. `ccswitch add <name>`으로 만든 프로필로 실행한 세션에서 default의 스킬·커맨드·에이전트·
   규칙이 동작한다.
2. 그 세션에 default의 `CLAUDE.md` 지침이 적용되고, 같은 지침이 두 번 들어가지 않는다.
3. 새 프로필에 default의 `settings.json`·`keybindings.json`이 복사되어 있다.
4. 사용자가 루트 파일을 복사 목록에 등록할 수 있고, 등록한 뒤 만든 프로필에 그 파일이 복사된다.
   계정에 딸린 파일은 등록이 거부된다.
5. 원본의 스킬·커맨드·에이전트·규칙·`CLAUDE.md`를 고치면 그 내용이 이미 만든 프로필에도
   반영된다 (선행 확인 2의 결과에 따라 `sync`가 필요할 수 있다).
6. 프로필에서 복사본을 고친 뒤 `sync`를 부르기 전까지는 고친 내용이 유지되고, `sync`를 부르면
   원본 기준으로 돌아간다.
7. 이 feature 전에 만든 프로필에 `sync`를 부르면 공유 자산이 구성된다. 그 자리에 사용자가 만든
   실제 파일·디렉토리가 이미 있으면 덮어쓰거나 지우지 않고 무엇이 충돌했는지 알린다.
8. 공유 자산이 있는 프로필을 `rm`으로 지워도 원본이 그대로 남고, 같은 이름으로 다시 만들면
   공유 자산이 다시 구성된다.
9. 원본에 공유 대상 디렉토리나 파일이 없어도 `add`가 실패하지 않는다.
10. `add`·`sync`가 실패하면 stderr에 무엇이 실패했는지와 조치가 표시되고 종료 코드가 0이 아니며,
    공유 원본은 바뀌지 않는다.
11. README의 "무엇이 나뉘고 무엇이 공유되는가"와 사용 절차가 실제 동작과 일치한다.
